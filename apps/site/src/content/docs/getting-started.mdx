Create a website you own: your content, your Git repository, your hosting account. Alkemist can supply one component, an optional visual system, or a complete generated site. Start with a coding agent or follow the same steps in a terminal.

**Release channels:** `canary` follows verified main revisions and carries the documented API. It may include breaking changes; commit your lockfile and review upgrades. The older `1.0.0-beta.1` registry release uses the earlier interface. The source generator remains available below.

## Install from npm

```sh
npm create alkemist@canary -- my-lab --provider cloudflare
cd my-lab
npm install
npm run verify
npm run dev
```

The generated site pins a coordinated package version. For an existing Astro site, use `npm install --save-exact @alkemdotdev/alkemist-components@canary`, adding the theme and integration from the same channel when needed. The [release guide](https://github.com/alkemdotdev/alkemist/blob/main/docs/publishing.md) explains automated canaries and deliberate beta/stable releases.

## Add one component

For an existing Astro application, start from a source-generated site or pack
the current source packages into your project. Then import the component
directly. No generated theme or integration is required:

```astro
---
import Chart from '@alkemdotdev/alkemist-components/chart';
---

<Chart
  title="Measured values over time"
  description="Readings from the accompanying CSV."
  src="/data/measurements.csv"
  type="line"
  x="time"
  y="value"
/>
```

## Add the optional theme or integration

Use `@alkemdotdev/alkemist-theme` when you want the board tokens, CSS, or
browser theme helpers. Use `@alkemdotdev/alkemist-astro` only when you want
Alkemist's integration and MDX defaults. Components remain usable without
either package.

```ts
import { defineConfig } from 'astro/config';
import alkemist from '@alkemdotdev/alkemist-astro';

export default defineConfig({ integrations: [alkemist()] });
```

## Use the source generator

Use Node **24.20.0**, clone the repository, and generate into a new, empty directory when you want the tarball-backed source workflow and its explicit update command:

```sh
git clone https://github.com/alkemdotdev/alkemist.git alkemist-source
cd alkemist-source
npm ci
npm run create:site -- ../my-lab --provider cloudflare
cd ../my-lab
npm install
npm run verify
npm run dev
```

Use `--provider gitlab` for GitLab Pages or `--provider custom` for another static host. Open the local address printed by Astro. The generator refuses a nonempty destination and does not create a remote repository, push code, or deploy your site.

The result is a standalone Astro application. Its package snapshots are stored as npm tarballs under `vendor/`, so it does not need the original checkout to install or build. Keep those tarballs and the generated `package-lock.json` in Git.

## Make it yours

Edit the site identity and navigation in `src/lib/site.ts`. Replace the example blog, lab, information page, and favicon with your content. Shared behavior stays in the packages; your content, configuration, and custom styles stay in your application.

The source starter offers optional **Blog · Logs · Labs · Docs · Book**, plus **Info**, with a small Test page under More. Choose only what your project needs: developed writing, quick notes, interactive apps, reference, or a curated learning path. These are conventions you can change. See [site structure](/docs/site-structure/) for configuration. The starter's `AGENTS.md` describes ownership, commands, hosting, and the verification steps for a coding agent.

Charts and models use their currently documented explicit props and public asset URLs. Portable source-relative figures and metadata sidecars remain proposed APIs; the setup generator does not make those forms available yet.

## Put it on the web

Create the destination repository in your own Git account, commit your site, and follow one hosting recipe:

| Host             | Deployment workflow                                                        | Guide                                             |
| ---------------- | -------------------------------------------------------------------------- | ------------------------------------------------- |
| Cloudflare Pages | Native Git builds; main production and other-branch previews               | [Cloudflare setup](/docs/hosting/cloudflare/)     |
| GitLab Pages     | GitLab CI; default branch production, with optional paid parallel previews | [GitLab Pages setup](/docs/hosting/gitlab-pages/) |
| Another provider | Static `dist/` artifact and the provider's own Git/upload workflow         | [Custom hosting setup](/docs/hosting/custom/)     |

Each guide covers repository setup, URL configuration, domains, build settings, and live verification. The generated site's publish directory is **`dist`**. The Alkemist demo's `apps/site/dist`, account IDs, and Cloudflare operator configuration belong to this website and should not be copied into your hosting setup.

Set `SITE_URL` to the final public origin. Use `BASE_PATH` if the actual address includes a project path, such as `/my-lab/`. GitLab Pages may assign a unique domain instead; use the provider's real URL and the [base-path instructions](/docs/hosting/gitlab-pages/#set-the-origin-and-base-path).

## What to give an agent

The copyable prompt above selects a hosting recipe. The [complete plain-Markdown instructions](/docs/agent-setup.md) cover inspection, generation, customization, deployment, and verification without requiring the agent to operate this interface. An [index of agent resources](/llms.txt) links to the same source material.

A useful starting request supplies your site name, intended directory or repository, hosting provider, and domain if you have one. The agent should recover existing settings from your workspace and ask for the missing details together. Its final report should include a working URL and observed deployment evidence, or identify the exact account-dependent step that remains.

## Keep a source-generated site updatable

From a reviewed newer Alkemist source checkout, use the explicit update mode:

```sh
npm ci
npm run create:site -- ../my-lab --update
cd ../my-lab
npm install
npm run verify
```

Review the package and lockfile changes, then exercise your customized pages. The update mode refreshes package snapshots and dependency references; it preserves site-owned content and configuration. The consumer check tests that boundary, including a subpath build. It is not a guarantee that every future major version needs no migration.

`--update` belongs only to the source generator because it refreshes the committed tarballs. The registry generator deliberately has no update command and never rewrites user files after creation; upgrade its dependencies with ordinary package-manager changes and the release notes.

## Contribute to Alkemist itself

To work on the demo and packages, use `npm run dev` in the source repository instead of generating a new site. `npm run verify` checks the demo; `npm run check:starter` installs and exercises a separate generated consumer. The [demo deployment guide](/docs/deployment/) describes this website's existing Cloudflare integration.
