The homepage has its opening image. This pass makes the rest of the site easier to use: shorter introductions, smaller headings, and direct paths from an example to its source.

## Find the component

The [documentation](/docs/) is grouped into getting started, components, customization, and hosting. Project and operator references sit separately. The [component catalog](/docs/components/) includes working previews, minimal usage, and links to the full contracts. Long reference pages have an on-page contents menu.

## Inspect and reuse it

Charts, models, and shaders now share figure spacing, title treatment, control styling, and source placement. Each keeps its own useful controls. Loading, errors, original downloads, and synthetic-data labels remain visible when they matter.

The [test page](/test/) keeps its long collection of examples. Section links come first, and source disclosures put the component markup, reference, and relevant files beside the rendered result. The examples use the actual demo data and models.

## A smaller header

Phones now use a single-row header: identity, appearance, and navigation. The hamburger opens the same main and secondary links; desktop keeps Blog, Labs, Docs, Info, and More visible. Docs is a primary link because using the toolkit starts with its reference. More holds Test, with a small downward chevron indicating the menu. A small icon replaces the theme dropdown, with labeled Whiteboard, Blackboard, and System choices. Keyboard support and saved preferences stay intact.

The header lives in the shared layout, so consuming sites receive the same behavior with their own links. Labs now uses a typed theme helper instead of reaching into the header's form controls. See the [navigation reference](/docs/site-structure/) for customization and the browser theme API.

## Keep the history accessible

[Labs](/labs/) opens with working tools. Earlier homepage and sculpture comparisons remain under Design studies, at their existing URLs. The [blog](/blog/) is a compact dated list, and [Info](/info/) describes the project and its current source-access requirements.

Reusable figure styling and type defaults belong to the UI package. Documentation navigation, source disclosures, and page composition belong to this site. That keeps the toolkit useful without making every consuming site a copy of Alkemist's own documentation.

## Remove repeated labels

The homepage's math entry previously said “MDX + math + code,” then “Write with math and code,” then “Write & explain.” One link was described three times. It now has one heading, “Math and code,” and a sentence naming what it supports.

The same edit removes repeated Documentation and Test labels, the small categories above Labs tools, and stacked labels on the homepage's project links. Setup keeps its provider choice, commands, agent prompt, and access requirements, with less introductory text. Figure names, units, source labels, and scientific limitations remain: those tell readers something they need to know.

## Let the artwork stand on its own

The opening sculpture no longer carries the study viewer's toolbar, “Drag to turn” hint, handwritten note, or caption rule. It is simply the homepage artwork. Its gentle motion and drag interaction remain; clicking the art or pressing Space or Enter while it is focused toggles motion. Reduced motion starts still, and the image stays in place if graphics are unavailable. The [field study](/labs/field-studies/?take=flux) keeps its full inspection controls. The [homepage guide](/docs/homepage/) explains how the two presentations share the same geometry.
